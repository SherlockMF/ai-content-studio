# 选题 · 发布 · 改稿清单

**读者**：出选题、写稿、跨平台发布的人  
**用途**：发前对照；不是流量诊断报告。  
**依据**：2026-08～09 公众号/贴图/小红书后台数据与审核处置。

**项目内生效方式**（不依赖 Cursor）：

- 人读完整清单：本文
- 代码规则模块：`src/lib/content-ops/topic-publish-revision.ts`（选题/出稿提示词注入；小红书引流检测；公众号贴图提醒）
- 发布面板：小红书「无站外引流」为阻断项；公众号发布检查含贴图一文双发提示

---

## 0. 先记住的三条

1. **公众号「一文双发」（文章 → 贴图）可以继续用**，不是误发；贴图会优先推非粉丝。差在贴图封面，不在「发了两条」。
2. **小红书严禁站外引流**：微信号、二维码、链接、外站 logo/水印、含义不清的数字串 → 可能直接限制推荐和搜索。
3. **冷启动优先「能验证的对象」或「场景痛点」**，少连续发抽象框架/纯观点文。

---

## 1. 选题

### 优先排期（更容易起量）

| 类型 | 例子 | 用法 |
| --- | --- | --- |
| 场景痛点 | 商品图看着能用、商家不敢用；服务收费先说清交付到哪一步 | 周主菜；配大字痛点封面/贴图 |
| 案例 / 盲测 / 自建工具 | 盲测报告、可点着看的小工具 | 每周至少 1 条，带可验证对象 |
| 争议 / 反常识（有证据） | 狂招全栈的真相；先掏空岗位再谈替代 | 穿插；标题有冲突点，正文给证据 |

### 控制用量（适合巩固人设，不适合连发）

- 抽象框架：「岗位=任务包」、能力结构模型、方法论总论
- 连发三天以上的纯观点判断
- 标题过长、半截、发后再改核心标题

### 选题自检（出题时勾）

- [ ] 这一条属于哪一类？若是「抽象观点」，本周是否已有案例/痛点文托底？
- [ ] 标题能否在手机封面缩略图里 **1 秒读完**？
- [ ] 是否与近两周已发标题/核心观点重复？（重复则换角度，不换皮重发）
- [ ] 小红书版是否避开医疗/健康里容易被误判的「留存玩法、导流」口吻？

### 建议周配方

- 1 条：场景痛点 + 强封面  
- 1 条：案例 / 盲测 / 工具  
- 0～1 条：争议观点（有证据）  
- 观点文不连发超过 2 天  

---

## 2. 发布

### 2.1 公众号 + 贴图

- [ ] 正文标题定稿后再点发布；少发后「已修改」改标题
- [ ] 官方生成贴图草稿后：**先改贴图封面文案，再发布贴图**
- [ ] 贴图封面：大字痛点 > 精美信息图 / 复杂产品拼图
- [ ] 首发时段避开 0:00–2:00；优先午后或晚间
- [ ] 一文双发保留；不要把贴图当成「又发了一篇同题水文」而删掉增长路径
- [ ] 跑完站内「发布前检查」（去 AI 味 → 补图 → 质检）再复制到后台

### 2.2 小红书（合规优先于增长话术）

发前必须清扫：

- [ ] 无微信 / QQ / 手机 / 邮箱 / URL
- [ ] 无二维码、邀请码、暗号式数字串
- [ ] 无外站 logo、水印、评测导流、福利诱饵跳转
- [ ] 评论区与主页简介同样清扫（平台会连坐提示）
- [ ] 封面大字可读；复杂 UI 拼图仅作内页，不作封面主图
- [ ] 从公众号搬文时做 **平台版清洗**，不要原样粘贴导流段

若审核「未通过 / 限制推荐和搜索」：先改笔记去敏感信息，再申诉；未修复前不要连发同题。

### 2.3 跨平台同步

- [ ] 先定「本平台要留下的动作」（关注、收藏、评论），不为导去另一平台而写
- [ ] 专名、数据、案例与公众号事实基线一致；平台差异只改结构与合规，不改事实

## 3. 改稿

### 什么时候改

| 信号 | 动作 |
| --- | --- |
| 有阅读、几乎 0 赞藏评 | 改 **开头三屏 / 钩子 / 结论前置**，不急着同题再发 |
| 阅读极低（个位数）且封面弱 | 优先换封面/贴图文案，再考虑改标题 |
| 小红书被限流 | **先合规修复**，再谈文案优化 |
| 事实错误 / 质检高优先级问题 | 定点改；改后重新质检 |
| 只想「再冲一波」 | 禁止同日同题连发第二篇正文；贴图除外 |

### 改稿原则

- [ ] 先定标题再动正文；尽量不改已发出的核心标题
- [ ] 定点修改（勾选质检问题）优于全文重写
- [ ] 不凭空补事实；缺证据就删判断或降调
- [ ] 公众号：改完再跑发布前检查 / 质检
- [ ] 小红书：改文案后核对配图文字是否仍一致；平台版再过一遍合规清单
- [ ] 有量无互动：把结论、清单或「可立刻用的一步」提前到前三屏

### 改稿时避免

- 用「再发一条同题」代替改开头  
- 在小红书加微信号/二维码「方便私聊」  
- 发后频繁改标题导致「已修改」刷屏  
- 连续用抽象金句堆砌，没有例子或步骤  

---

## 4. 发后 24～48 小时看什么

1. **贴图是否吃到非粉**：有初步阅读但无互动 → 改钩子；几乎无阅读 → 查封面与时段。  
2. **小红书是否进推荐/搜索**：若被限制，先看审核详情，别继续堆量。  
3. **是否该补一条「证据型」内容**：若本周已连发观点，下一条改案例或工具。  

---

## 5. 给协作 AI 的一句话指令

> 出选题时按「痛点 / 案例工具 / 争议」轮换，控制抽象观点密度；公众号可保留文章+贴图双发并先磨贴图封面；小红书必须去引流与外链；改稿优先开头与合规，禁止同日同题再发冲量。
