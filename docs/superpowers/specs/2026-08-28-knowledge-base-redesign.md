# 知识库全面改版设计

## 目标

将现有短文本“素材库”升级为可上传笔记文件、检索内容并在 AI 生成前确认引用范围的知识库，同时保留观点、案例、常用表达和禁止表达等已有素材。

## 产品结构

- 导航显示“知识库”，保留 `/materials` 地址兼容旧入口。
- “资料文档”支持批量上传 `.md`、`.markdown`、`.txt`、`.docx`、`.pdf`，显示解析状态、标签、大小、更新时间、启用状态，并提供搜索、预览和删除。
- “知识条目”承接现有素材，支持新增、编辑、筛选、启停和删除。
- 选题研究与稿件生成区域显示“本次参考资料”：系统按当前选题自动推荐，用户可搜索、勾选或移除后再生成。

## 数据与检索

- 大文本和分段写入浏览器 IndexedDB；现有业务状态仍使用当前 App Store/localStorage。
- 文档按自然段切分，保存文档元数据、解析正文和片段。
- 首版检索使用标题、标签、正文关键词的加权评分，不引入 embedding 依赖；接口保留以后替换为向量召回的边界。
- AI 请求仅携带用户确认的知识片段，并为每段附带来源标题；不发送完整知识库。
- Supabase migration 补充 `knowledge_documents` 与 `knowledge_chunks`，用于后续远端同步；未配置 Supabase 时本地功能完整可用。

## 文件处理

- `.md`、`.markdown`、`.txt` 在浏览器直接读取。
- `.docx`、`.pdf` 通过 `/api/documents/extract` 解析。
- `.doc` 明确提示转换为 `.docx`。
- 对空文件、解析失败和过大文件给出明确状态；单文件限制 10 MB。

## 兼容与迁移

- 不改变 `MaterialItem` 的既有含义，旧素材无需迁移即可继续使用。
- AI 接口新增可选 `knowledgeReferences`，旧调用方不传时行为不变。
- `/knowledge` 继续重定向 `/materials`。

## 验收标准

1. 上传支持格式后可看到解析成功的文档并预览正文。
2. 刷新页面后文档仍存在，且大正文不进入 localStorage。
3. 可搜索、启停和删除文档；可完整管理旧知识条目。
4. 选题与稿件页面会自动推荐相关片段，用户可以增删确认。
5. AI Prompt 包含已确认片段的来源标题，不包含未选择文档。
6. lint、TypeScript 和生产构建通过。
