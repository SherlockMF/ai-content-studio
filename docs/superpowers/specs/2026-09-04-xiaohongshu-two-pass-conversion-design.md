# 小红书两步转换设计

## 目标

解决公众号长文（尤其测评/对比稿）一键转小红书时过度压缩、主体覆盖不全的问题。例如开场写「测了 4 个 agent」，正文却只展开其中一两个。

保持「一张长笔记」形态，不拆系列；也不要求接近公众号 4000+ 字篇幅。

## 目标字数

- `professional`：1200～1600 字
- `social`：900～1300 字

## 转换流程

服务端两步，对客户端 API 仍一次返回：

1. **抽大纲**（不落库、不展示）  
   从公众号正文抽出：`subjects`、`keyFacts`、`roundConclusions`、`overallJudgment`、`optionalDetails`。
2. **按大纲写稿**  
   用大纲 + 原文写两版文案与共用 `imagePlan`。硬约束：`subjects` 中每个主体正文至少有一段独立结论；开场若声明「测了 N 个」，正文主体数必须等于 N。

## 数据结构

内部大纲 schema（仅服务端）：

```ts
{
  subjects: string[];
  keyFacts: string[];
  roundConclusions: string[];
  overallJudgment: string;
  optionalDetails: string[];
}
```

对外响应、编辑器 UI、版本存储、发布面板不变。

## 写稿与质检规则

- 事实只来自大纲与原文；禁止虚构亲测/使用时长/结果提升。
- 字数不够时优先压缩 `optionalDetails`，不得删主体结论与关键数字。
- 图片仍 5～8 张，优先覆盖各主体结论、轮次差异与总判断。
- 质检新增「主体覆盖」维度：对照来源正文点名主体检查是否齐全。

## 现有稿件

规则上线后，对已有小红书稿点击「重新转小红书」覆盖生成即可。

## 不改范围

- 客户端请求/响应字段
- 编辑器布局与发布面板
- 自动发文或真实生图
