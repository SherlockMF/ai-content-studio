# 公众号「发布前检查」流水线

**日期**：2026-09-22  
**状态**：已确认，进入实现

## 背景

原「检查并补齐配图」只做配图检查与补齐。发布前还常需去 AI 味与质检，希望一次点击按顺序完成。

## 入口

- 主文案：`发布前检查`
- `title` 提示：`去 AI 味 → 补图 → 质检`
- 独立「运行质检」按钮保留，可单独重跑
- 「AI 润色 / 重新生成」自身流程不变；小红书流程不动

## 流程（一次点击，顺序执行）

1. `flushAutosave`
2. **去 AI 味**
   - 跳过条件：`source === "ai"` **或** 版本历史已有 `ai_rewrite`（已 AI 润色）
   - 依据：从零出稿已在 `generateWechatArticlePipeline` 内调用 `deAiRewrite`（human-writing + khazix-writer）
   - 未跳过时：测评稿用 `preserve_structure`，否则 `polish`；成功后以 `ai_rewrite` 落盘
3. **补图**
   - 无论正文是否已有 markdown 图片位，都调用现有 `generateWechatMedia`（`/api/ai/wechat/media-plan` + 生图）
   - 无图时由 media-plan 规划封面 + 至少三张正文图并生成；有图时匹配保留、缺图补齐
   - 进度：`检查配图…` / `规划并生成配图…`（及现有逐张进度）
4. **质检**：现有 `runReview`，写入质检结果

## 失败策略

- 去 AI 味失败 → 停，不补图、不质检
- 补图全部/部分失败 → toast 提示，**仍继续质检**
- 质检失败 → 只报错，不回滚正文与配图

## 进度文案

- `去 AI 味中…` / `已去过 AI 味，跳过`
- `检查配图…` / `规划并生成配图…`（及现有逐张进度）
- `质检中…`

## 实现约束

- 前端串起现有 API 与客户端配图执行器，不新增服务端 pipeline
- 可测逻辑（跳过判定、无图判定、步骤文案）抽到纯函数模块
