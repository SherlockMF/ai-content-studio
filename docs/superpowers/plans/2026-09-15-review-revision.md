# 质检条目修改实施计划

**目标**：公众号和小红书质检结果支持勾选问题，按选择自动修改并保存版本。

**方案**：复用现有 DeepSeek provider、版本存储和编辑器。共用质检面板只发送勾选的问题；服务端返回可定位的文字替换，校验后应用，避免全文重写。小红书只改当前语气版本，配图方案变更后对应旧图失效。请求期间稿件或来源变化时丢弃结果。修改后需重新质检。

**约束**：不添加依赖，不覆盖已有其他稿件，不自动发布。模型不得凭空补充缺失事实。标题超过 20 字时返回错误，禁止截断。公众号质检增加正文快照，旧结果只供参考。

- [x] 编写并运行 `src/lib/review-revision.test.ts`：选中问题映射、唯一文本定位、原子失败、图片失效、标题限制、来源变更。
- [x] 实现 `src/lib/review-revision.ts` 和 `src/lib/ai/review-revision.ts`；增加 `api/ai/review/revise` 参数校验与错误测试。
- [x] 增加 `ReviewIssuesPanel`，替换两处只读问题列表；对接各自保存与版本记录。公众号新质检绑定当前文稿快照。
- [x] 跑定向测试、typecheck、lint，在浏览器验证勾选、自动修改、版本保存与失败不覆盖。

验收必须基于实际命令和浏览器结果；不把模型的修改说明作为新质检通过证明。

追加需求：小红书复制同时提供 text/plain 与显式 br HTML，保留原换行与空行；自动排期按平台工作日容量、题材相似度、板块轮换、热点及完成度安排，新增选题保留预排且参与重排，手动日期和已发布保留。用户要求控制测试范围，仅运行关键定向测试、类型检查及页面关键操作。

验证记录：质检修改 10 个定向测试通过；自动排期及原顺延逻辑 6 个定向测试通过；复制逻辑 2 个定向测试通过；类型检查通过。两平台浏览器验证了勾选修改、版本保存、旧质检失效；剪贴板两种格式换行与原文一致。正式库已开启自动排期，14 篇自动安排。原编辑器仍有既存 React refs/purity 等 lint 报错，已与 HEAD 基线对照；本次新增模块 lint 通过。未实际向小红书发布或粘贴到其外部发布页。

后续修正：浏览器验证的隔离措施未完全生效，导致正式公众号稿出现测试标题、测试质检和测试版本。已从历史版本恢复原标题，移除对应测试记录，修正两处排期说明中的测试标题引用；刷新后核验正文、图片、状态及排期未改变。日期导航已排除归档稿，解除归档后重新显示。自动排期已取消中午截止限制，当天晚间仍可安排当天空位，新增定向回归测试通过。文稿恢复及实际日期调整保存在浏览器数据中，不属于 Git 代码提交。
