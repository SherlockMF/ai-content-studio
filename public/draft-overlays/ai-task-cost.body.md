一个 AI 客服回答得很快，后台显示调用成本也很低。但用户绕了一圈，最后还是转人工，把同一个问题重新说了一遍。

这笔账应该怎么算？

模型确实工作了，费用也确实发生了。可从用户提出问题到事情解决，团队可能多付了一轮沟通成本。AI 项目有没有商业价值，得沿着这条完整路径算。

**我更愿意先看一个数，每完成一项合格任务，实际花了多少钱。**

## 先把“成功”写得足够具体

假设你在做一个报销材料检查助手。用户上传发票和申请单，系统找出缺项、金额差异，再把结果交给财务。

如果成功标准只是“生成了一份检查报告”，系统很容易达标。报告里有没有漏掉关键问题，财务能不能直接使用，却仍然未知。

换一种验收方式。检查金额与原始材料一致，缺项定位到具体文件，无法识别的内容明确留空，财务复核后无需重新做一遍。到这里，成功才对应真实工作。

Anthropic 的 Agent 评测说明也区分了执行记录和最终结果。系统声称完成任务，还需要看外部环境里是否真的产生了目标结果。[来源](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

实际统计时，可以把任务分成自动通过、人工修正后通过和失败。需要人工接手的任务不必一律算产品失败，但不能混进“全自动成功”里。

## 失败的费用，也要由成功任务承担

下面是一组假设数据，仅用于说明计算方法。

某个助手在一个统计周期内收到 100 次任务。60 次自动验收通过，20 次经过人工修正后通过，另外 20 次仍未完成。

| 成本项目 | 假设金额 |
| --- | ---: |
| 模型与工具调用，含失败和重试 | 200 元 |
| 人工复核与返工 | 300 元 |
| 分摊到本批任务的运行维护成本 | 100 元 |
| 合计 | 600 元 |

如果服务承诺允许人工兜底，这批任务有 80 次最终合格交付，平均每次成功交付的成本就是 600 ÷ 80，等于 7.5 元。

![单次成功交付成本](/article-assets/img_bdb4087420af8591.png)

<!-- GPT 配图提示词
数据信息图：调用 200 元、人工 300 元、维护 100 元，合计 600 元；公式 600÷80=7.5 元/次成功。旁注 100 次任务中 60 自动、20 修正、20 失败。
-->

如果承诺的是全自动完成，还必须另外报告 60% 的自动通过率。不能拿经过人工修正的 20 次，为自动化能力撑场面。

这里最容易漏算的是失败任务。它们没带来交付，却同样消耗了资源。只统计成功样本里的一次 API 调用，会把真正的成本藏起来。

这 7.5 元也还不是公司的完整利润账。获客、前期研发、退款以及其他固定投入，需要按自己的业务口径继续核算。先算清交付成本，是为了知道产品每多接一单，会发生什么。

## 用少量指标，把问题定位到具体环节

初期不必急着做几十项指标的大屏。我建议先维护一张能追溯到任务的表。

| 指标 | 主要回答什么问题 |
| --- | --- |
| 自动验收通过率 | 有多少任务能直接交付 |
| 人工介入比例与耗时 | 还有多少工作留给人 |
| 单次成功交付成本 | 失败与返工之后，成本是否可承受 |
| 完成耗时的中位数与 P95 | 普通用户和等待最久的一批用户，分别要等多久 |
| 同类需求再次使用比例 | 用户下次有同样问题时，还愿不愿意回来 |

![用少量指标定位问题](/article-assets/img_007f00b753a2a717.png)

P95 可以理解为，约 95% 的任务在这个时间以内完成。平均耗时看着不错时，仍可能有一批任务长时间卡住。

这些指标要一起读。人工介入下降，可能是系统更可靠，也可能是转人工入口变难找了。成功率上升，可能是能力提升，也可能是团队把难题移出了测试集。

所以每次数字变化，都应该能点开一组具体任务，看输入是什么、在哪一步失败、谁修了多久。

## 给不同任务分开记账

一个助手可能同时处理简单查找和复杂核对。把两者混在一起，容易得出错误判断。

简单查找量大、成本低，会掩盖复杂核对的失败率。反过来，一小部分复杂任务耗时很长，也可能让团队误判整个产品都不值得继续做。

可以先按任务类型和难度分组，再看各组的成功率与成本。模型换版或者规则调整后，用一批固定样本回归测试，同时补进真实使用中新出现的问题。

固定样本用来判断有没有退步，新样本用来检查产品是否还适合当前业务。两种材料都需要。

## 省下的时间，最后去了哪里

“员工少花两小时”是一个有用的起点，但它需要继续往下追。

这两小时有没有被检查 AI 输出吃回去？员工是否因此多处理了订单？客户等待是否缩短？还是只是把一段劳动换成另一段劳动？

如果节省的时间没有变成更高产出、更短交付周期或实际成本下降，就先把它记为潜在收益，别急着当成已经到账的利润。

下一次看 AI 项目的演示，可以请团队随机打开几笔真实任务。顺着原始输入、最终成果和返工记录走一遍，再拿出这一批任务的完整费用。

这时候，继续优化模型、缩小服务范围，还是调整收费，才有具体依据。
